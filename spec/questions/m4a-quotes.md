# Module 4A (catalog balancer API) — questions and assumptions

Each row was implemented with the recommended variant. Contract: `spec/modules/4a-quotes.md`.

| # | Question | Implemented (recommended) | Alternatives |
|---|---|---|---|
| Q-1 | B-02 "a CBD component unknown to the catalog fails the quote with a clear reason" — an HTTP error or a failed quote set? | `200` with every factory `producible: false`, reason `UNKNOWN_COMPONENT`, the component line marked `stockStatus: "unknown"`; the set is stored so the decision log can link to it | `422` with the unknown ERP IDs and nothing stored |
| Q-2 | How are invalid and dropshipper SKUs answered? What about a SKU the catalog does not know? | Invalid (S-11): every factory `SKU_INVALID`. Dropshipper (B-07): every factory `DROPSHIPPER`, no components / processes. Both stored. Unknown SKU: `404` (a quote set cannot be stored without a SKU) | `422` for all three; route invalid SKUs anyway with a warning |
| Q-3 | Does a retired SKU (`status = Retired`) still get quotes? | Yes — an order paid before retirement must still be produced; the producible flags decide | Reason `SKU_RETIRED` on every factory |
| Q-4 | Quotes: check only the CBD (B-02), or also Static components of the SKU mapping that are missing from the CBD (the S-17 rule of the legacy check)? | Only the CBD is checked and priced, as B-02 says ("every Static component plus the Dynamic ones the customer selected" are already in it). The legacy eligibility check does add the SKU's Static components (S-17) | Add missing Static components to the quote as well; fail the quote when the CBD lacks a Static component |
| Q-5 | Is `cbd[].quantity` per piece or for the whole order item? | Per piece: required quantity = `cbd.quantity × quantity`; `components[].quantity` and `processes[].quantity` in the answer are the totals | CBD quantity already covers the whole item |
| Q-6 | Capacity signal formula ("from stock and today's remaining process capacity, 0–100") | Minimum of: 100 / 50 for each consumed component with stock `ok` / `low` (the alternative's status when used) and today's remaining % of each mapped process | Process capacity only; a weighted average; stock coverage (stock ÷ required quantity) |
| Q-7 | "Used today" (P-14): what is counted and which day? | Quotes with status `Produced` and `produced_at` in the current **UTC** day in that factory whose SKU maps the process — one per order item (reproductions included), not multiplied by item quantity. Without `max_per_day` the remaining % equals the set capacity % | Count pieces (`quantity`); factory-local day; count selected-but-not-produced items too |
| Q-8 | Component unit cost / labor cost missing (C-10 is still open) or in another currency | Missing cost counts as 0 and the quote carries `COMPONENT_COST_MISSING` / `LABOR_COST_MISSING`; the quote currency is `Quotes:Currency` (default `USD`); lines in another currency are summed as they are and flagged `CURRENCY_MISMATCH` (no FX source exists) | Make the factory non-producible when a cost is missing; convert currencies |
| Q-9 | P-11 "packing cost is included in every production quote" when the SKU has no `PACKING` mapping | Packing is priced only from the SKU's `PACKING` mapping (`quantity ×` the factory's packing labor cost) and reported separately; without a mapping `cost.packing = 0` and the quote carries `PACKING_NOT_MAPPED` | Add packing implicitly with quantity 1 per piece for every SKU |
| Q-10 | A mapped process the factory does not run (`runs_here = false` or no `process_factory` row) | Factory not producible, reason `PROCESS_NOT_AVAILABLE` (extra code, not in the requirement samples). The legacy check ignores "runs here" and only looks at 0 % | Ignore "runs here" in quotes; report it as `PROCESS_OFFLINE` |
| Q-11 | "For balancer" alternatives: which one, how priced, does the stock quantity matter? | Alternative must be an active component and not out of stock in that factory; prefer stock `ok` over `low`, then the lowest ERP ID; the line is priced with the alternative's unit cost; alternatives are one-way and not chained; stock is not compared with the required quantity (the shared stock rule only knows `total <= 0`) | Price with the original's cost; require stock ≥ required quantity; follow alternatives of alternatives |
| Q-12 | "Every factory is returned" — inactive factories too? | Active factories only (`factory.is_active`) | Return inactive factories with a reason |
| Q-13 | `quoteKey` when an order item is quoted again (transfer re-quote, shadow next to live); key length | First set `PQ-{orderId}-{orderItemId}`, later sets `…-R2`, `…-R3`; estimates `EST-{requestId}` (never stored). `orderId` / `orderItemId` are limited to 90 characters so the key fits `quote_key` (200) and `quote_id` (220) | Key from `requestId`; a sequence column; widen the columns |
| Q-14 | Quote validity (`validUntil`) and whether the lifecycle enforces it | 15 minutes (as the requirement sample), configurable with `Quotes:ValidityMinutes`; informational only — `select` does not reject an expired quote, so a slow decision never leaves an order unrouted | Reject `select` after `validUntil` with 409 |
| Q-15 | Conflict rules of `select` | 409 for a non-producible quote, for a quote that is `Produced` / `Transferred`, and when another quote of the same set is `Selected` / `Produced`; repeating the call is a no-op. Other sets of the same order item are not checked. Shadow sets may be selected | Allow selecting a non-producible quote (manual override); one selected quote per order item across sets; forbid selecting shadow quotes |
| Q-16 | Reproductions (decision of Nov 24): how does the caller address them and what is the "new produced record"? | `POST /v1/quotes/{quoteId}/produced` with `reproductionOfQuoteId` = the originally produced quote. If `{quoteId}` is already `Produced` (normally the original itself) a new `quote` row is created in the same set (`{quoteId}-RP{n}`, copy of costs, status `Produced`, `reproduction_of_quote_id` set). If `{quoteId}` is a different, `Selected` quote (item re-quoted elsewhere) that quote becomes `Produced` and is linked. Idempotent on (original, `producedAt`, factory). A second "produced" without the link and with another date is a 409 | A dedicated `/reproduced` endpoint; a separate `quote_production` table |
| Q-17 | S-16: exact format and transport of the country SKU lists; how a catalog factory maps to a TG Supplier country balance / packing center | `GET /v1/legacy-balancer/country-sku-lists` returns, per active factory, the TG Supplier field names (`countryName`, `skus[{ id, sku, producible, removed }]`) found in `supplier_api` (`CountryBalanceSkuResponse`). One entry per Site SKU and per alias; `id` = SKU UUID; `removed` = retired or not producible; `countryName` = factory name. TG Supplier must map `factoryId` to its country balance and decide whether it pulls on demand or syncs into `CountryBalanceSkus` | Push the lists into TG Supplier (`saveSkus`); export a file; only entries of producible SKUs |
| Q-18 | Who may call the writing endpoints (`POST /v1/quotes`, lifecycle, eligibility)? | Service accounts only (Basic auth): the handler returns 403 for a JWT user even while `permissions.enable_all` is off. Reads need `BalancerView` | A dedicated permission for operations; allow admins |
| Q-19 | Legacy eligibility when the SKU, a component or a factory is unknown | Unknown or missing SKU → only the CBD is checked (how Module 1 works before SKU mappings exist). Components unknown to the catalog never skip a factory and are returned in `unknownComponents`. Unknown factory ids → 422 (a missing stock row would otherwise read as "out of stock everywhere") | 404 for an unknown SKU; treat unknown components as OOS; ignore unknown factories |
| Q-20 | The legacy balancer re-evaluates orders repeatedly — one skip-log row per call? | The same cause (order, order item, factory, reason, component / process) is logged once per UTC day | Log every call; log once per order forever |
| Q-21 | Casing of enum-like values | Requests are parsed case-insensitively (`"live"`). Responses: C# member names for enums (`mode`, `status`, skip `reason`) per the API convention (FB-13); `stockStatus` is `ok` / `low` / `outOfStock` / `unknown` and reason codes are `UPPER_SNAKE`, as in section B | Lower-case everything as in the requirement samples |
| Q-22 | A CBD component that exists but is `Inactive` in SAP | Treated like any known component: stock decides | Reason `COMPONENT_INACTIVE` |
| Q-23 | "SKU resolved by UUID or alias" — is the Site SKU accepted? | Yes: UUID, then alias, then Site SKU when exactly one SKU has it (ambiguous → 422); matching is case-insensitive | UUID and alias only |
| Q-24 | Idempotent replay with the same `requestId` but a different body | The stored set is returned unchanged; only a different order item is rejected (409) | Compare the whole body and return 409 on any difference |
| Q-25 | Redistribution when the remaining producible factories all have a 0 share | Equal split among them, so shares still add up to 100 | All 0 |
| Q-26 | `process_factory.labor_cost_effective_from` | Ignored: only one rate is stored, so the current rate is used whatever the date | Use the rate only from its effective date |
| Q-27 | A process with capacity > 0 but nothing left today (P-14) | The factory stays producible with `remainingPct = 0` and `capacitySignalPct = 0`; the balancer decides (B-05 / B-08) | Reason `PROCESS_FULL` and not producible |
| Q-28 | Legacy lists and invalid SKUs (S-11 "bad data never reaches the balancer") | The country SKU lists and the legacy check do not look at the validation status, so current routing keeps working during the transition | Mark invalid SKUs not producible in the lists |
