# Foundation (backend) — questions and assumptions

Each row was implemented with the recommended variant.

| # | Question | Implemented (recommended) | Alternatives |
|---|---|---|---|
| FB-1 | Factory ids: the requirement JSON samples use `110`, `125`, `315` (and "at most 4 factories"), the mockup uses `KG` / `NZ` / `HU` / `TH`. Which ids, names and countries are real? | Seeded `110`, `125`, `315` with names `Factory 110/125/315`, `country_code` null, as the requirement pages support. `factory.id` is a free string, so the real list is a seed change | Seed four factories with mockup codes; add a separate `code` column; sync the list from TG Supplier |
| FB-2 | Role name for the new Shift manager persona | `FC-ShiftManagers`, same permissions as the factory manager, bound to a factory through `user_factory` | Put shift managers into `FC-FactoryManagers` and drop the role |
| FB-3 | Who edits a process's runs here / machine type / labor cost? The plan gave it to the catalog admin (`Processes.Edit`), the revised overview and the decision of Nov 23 give it to the factory manager; the mockup's `P1_CAN.editProcessFactories` still says catalog admin and lists it as an open item | New permission `ProcessesEditFactorySetup` for the factory / shift manager (own factory); `ProcessesEdit` stays with the catalog admin for specifications, new processes and import. Max per day (P-13) is covered by the same permission | Keep it with the catalog admin; allow both |
| FB-4 | "Supply chain manager edits … costs" (overview permissions table) vs C-10 "view only in Phase 1, source open" | Added `ComponentsEditCost` and `ComponentsViewCost` to the supply chain manager; no endpoint edits cost yet | Drop the permission until the cost source is decided |
| FB-5 | Balancer view for the production floor user: plan says no, overview table says "View" | Granted `BalancerView` | Keep it hidden |
| FB-6 | Permissions for the daily plan (B-22) and transfers (B-23), which the plan does not list | `BalancerViewDailyPlan` (factory / shift manager, own factory), `BalancerTransfer` (factory / shift manager own factory, operations any) | Reuse `BalancerView` |
| FB-7 | Should factory managers see process labor cost they edit? | Yes: `ProcessesViewCost` granted to factory / shift managers | Cost visible to admin and finance only |
| FB-8 | What does the own-factory check do while `permissions.enable_all` is off? | Everyone passes (consistent with "enforcement off = every authenticated user may do everything") | Enforce the factory binding regardless of the toggle |
| FB-9 | Production feedback after the Nov 24 decision: what stays in the catalog? | `production_event` table and the `ProductionTracking` module were dropped. `quote` keeps `status` (`Quoted/Selected/Produced/Transferred`), `selected_at`, `produced_at`, `transferred_at`, `reproduction_of_quote_id` and a `production_log` jsonb, so the balancer can mark a quote produced, P-14 "used today" can be derived, and S-20 "production conflict" can be derived from the reported log | Separate `production_event` table fed by the balancer; a `sku_production_conflict` table |
| FB-10 | Is `quote_key` unique when an item is re-quoted (transfer B-23)? The sample key is `PQ-{order}-{item}` | Unique index on `quote_key`; the quotes module decides the key format for re-quotes (e.g. a suffix) | Non-unique key plus a sequence number |
| FB-11 | Shape of `GET /v1/feature-toggle` ("as in the shipment service") | `{ "data": [ { id, name, isEnabled, description, createdAt, updatedAt } ] }` (the shipment service envelope; the frontend reads `response.data`). Toggles are global only (no site / facility scope) | Bare array like the other endpoints |
| FB-12 | What are `roles` in `GET /v1/user/me`? | Role names = AD group names (`FC-FactoryManagers`, …) resolved through `GroupPermissions.json`, as in the shipment service frontend | Short codes; raw token groups |
| FB-13 | Enum casing in JSON | C# member names (`"Active"`, `"Running"`, `"Machine"`), as the history `source` sample in the plan | lower-case as in the requirement JSON samples (`active`, `machine`) — module DTOs may map explicitly |
| FB-14 | Who may read sync status and history? | Any authenticated user (the UI shows "Last sync" to everyone); `SyncMonitor` is kept for run details, `SyncTrigger` for "Sync now" | Restrict status to the catalog admin |
| FB-15 | A sync that crashes leaves a `Running` row and would block the next run forever | A `Running` run older than 6 hours is failed as abandoned by the next `Start` | Manual cleanup; heartbeat column |
| FB-16 | Foreign keys from `sku_component` / `sku_process` to `component` / `process` | None: the master catalog may reference unknown components; such SKUs are flagged `Invalid` (S-11) | FK on `sku_process` only (import validates rows) |
| FB-17 | Where do alternatives' / replacements' audit rows go? | `history_entry` with the component as the entity; no FK from `history_entry.factory_id` | Dedicated audit tables |
| FB-18 | Component fields not in the requirement schema but in the mockup data (`supplier`) | Not stored | Add `supplier` when SAP exports it |
| FB-19 | `user_factory` maintenance UI | None in Phase 1; rows are inserted by ops / the catalog admin directly | Admin screen and endpoints |
| FB-20 | Text search / "contains" filters on large tables | `lower(column) LIKE '%…%'` with plain b-tree indexes on names and ids | `pg_trgm` GIN indexes when volumes require it |
| FB-21 | Hangfire dashboard authentication (the reference allows everyone) | Basic auth with the API service credentials | Azure AD cookie auth; open inside the cluster only |
| FB-22 | The API cannot start without PostgreSQL (Hangfire storage is created on startup) | Accepted, as in the shipment service | Config switch to disable Hangfire locally |
| FB-23 | Azure AD ids for local development | `appsettings.Development.json` reuses the shipment service tenant / client id (open question A-6); `appsettings.json` is empty | Dedicated app registration |
| FB-24 | Everything reusable sits in one project `Tenengroup.Infrastructure.Common`, which references ASP.NET Core, EF Core, Hangfire, ClosedXML and the AWS SDK | One project, as the task asked; the Balancer reuses auth, mediator, paging, excel, AWS from it | Split into `Common`, `Common.Web`, `Aws` |
| FB-25 | Dropshipper record: S-19 lists "ID, name, dropshipper and total cost", the schema only `dropshipperId` and `totalCost` | `sku.dropshipper_id`, `dropshipper_name`, `dropshipper_total_cost_amount/currency` | Separate dropshipper table |
